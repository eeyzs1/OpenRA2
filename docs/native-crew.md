# 来源乘员身份、开火和持续时空光束

最新 SourceScene37 / NativeCrew2 / LAN55 已实现原始 OpenTransportWeapon 固定槽、普通／精英及真实空地开火，见[乘员选枪](crew-weapon-selection.md)。下文保留 Scene36/Crew1 批记录及其证据；城市驻军完整顺序、特殊武器分派和独立原版校准仍未完成。

2026-11-18后续LAN54修复全局同格到达及AI建造顺序，来源乘员仍为Scene36/NativeCrew1。英国零出兵开局已修复，但原型与来源整局窗口失败尚存，见[最新验证](ai-arrival-and-build-order.md)。GI/GGI 的 OpenTransportWeapon 漏读已由后续 Crew2 批修复。

本页记录的乘员批合同为 **SourceScene36 / NativeCrew1 / NativeTemporal1 / NativeWeapons3 / NativeIFV2 / NativeProduction5 / World60 / App11 / LAN53**。地图战役仍为 SourceScene16。旧 Scene35 及更早的来源合同不启用新乘员管线。

## 实现范围

模拟由 `world_native_crew.cpp` 持有，邻域索敌由 `world_native_crew_targets.cpp` 持有，保存和校验由 `world_native_crew_save.cpp` 持有。场景解析使用独立 `native_crew_parse.cpp`。现有时空模块保存共享协作链；生命周期、登车和卸载只调用这些子系统。画面仍读取光束描述，不推进模拟。

Scene36 显式要求 `CrewVersion=1`、`NativeCrew` 总则及每个普通类型的乘员字段。从本机各版本自己的 MIX 导出 `OpenTopped`、`Occupier`、占领武器和总则，不能把 RA2 和 YR 的值合并。当前 YR 的要塞总则为射程加 2、伤害乘 1.2、移动后光束最大距离 7。

每个新生实体获得单调递增的 `combatActor`，登车时随实际乘员保存，卸载时恢复。实体槽位可以复用，乘员下标也会改变；两者都不能作为持续攻击或延迟弹道的最终射手身份。消耗、死亡和槽位复用清理退休记录，分配器不复用旧身份。未开火的人工匿名乘员记录可暂存零值，进入乘员开火路径前按确定顺序补发身份。

要塞内每名军团兵各有独立光束，可与外面的军团兵、时空 IFV 协作。它们共享目标的 Strength 预算、主节点接力及原始基础武器 Damage；载具的伤害加成、乘员的 FIREPOWER 和箱子伤害不会加速时空抹除。乘员晋升后按它自己的普通或精英武器更新扣减。

乘员光束以负的稳定身份编码为键，实体光束保留非负 EID。载具引用仍含出生代次。载具移动时保留距离内的乘员光束；超出原始距离时解除。成功卸载只解除实际离舱乘员，堵塞未离舱者保留。停止、转移攻击、乘员消耗、载具死亡、目标死亡和载具被冻结均清理对应关系；冻结载具同时暂停乘员计时。冻结载具取消乘员输出，也修正了原版已知的相关冻结遗漏。

普通乘员按各自来源武器和 ROF 开火。连射单独保留载具、目标代次、射手身份、剩余发数和间隔；间隔采用已有来源武器的 tick 换算，冻结时不消耗间隔或 RNG。索敌复用地面链、建筑占地及空中桶，候选按 EID 去重排序，保留确定性的平局次序。

RA2 城市驻军保留建筑的 `AlliedOccupyW` / `SovietOccupyW`；YR 使用每名驻军自己的 `OccupyWeapon` / `EliteOccupyWeapon`，应用该版本的 `OccupyDamageMultiplier` / `OccupyROFMultiplier`。原始军团兵没有 `Occupier`，不能进入城市建筑。坦克碉堡仍使用既有武器路径，同时获得稳定弹道归属。

普通发射、激光分裂和范围伤害显式传递射手身份。延迟弹道在射手登车、卸载、载具死亡或旧座位由新人占用后，不会把经验记给新乘员或载具。自行引爆的乘员消耗实际乘员，不会误杀整个载具。

## 自然对局暴露的侦察循环

首轮全量为 154/156，原 RA2 海岛种子 941 在固定 360000 tick 内没有结算。实际残局、41 组应用检查点和 240 tick 运动记录保留。检查发现飞机反复把黑幕中的脚下或已到达旧坐标当作新侦察目标，不能推进。

本批 SourceScene36 的侦察目的地跳过飞机当前传感范围内的黑幕点和已到达的旧联系点，保留旧联系记忆；武装飞机通过普通攻击移动探索。选择只读取自己的位置、视野参数、雾和旧记忆，不查询隐藏敌军来指定目标。Scene35 及更早保留原决策。`nativeSceneVersion` 从嵌入来源推导，不另存或单独散列。底层黑幕呈现与完整原始 AI 仍需继续校准。

## 保存与兼容

World60 在 Temporal 后追加 `CREW` v1。该块保存启用标记、身份序列、按实体及乘员遍历顺序排列的身份、弹道射手身份及按身份排序的待发连射。长度有界，检查计数、身份重复和序列上限、载具及目标代次、射手存在、连射范围、布尔字段和尾标。全部可变状态进入世界校验。

启用乘员时，`TEMP` 使用 v2：每条记录 56 字节，增加乘员身份并把协作链接扩大为 64 位。旧来源合同继续使用原 v1 记录与原校验。冻结主节点仍由图重建，不保存第二份可分歧状态。读取新块后一起验证图和乘员引用。

关闭的 CREW 块为 37 字节。真实历史夹具见 [World59 夹具](../tests/fixtures/native-crew-v59/README.md)：迁移比较仅去掉这个关闭块并还原格式标识，不能描述为两种存档格式的原始字节相同。低层 World 读入失败后由调用者丢弃；应用层使用暂存对象，失败保持当前游戏。复用新 World 读取旧 World 时必须清空残留身份、连射和弹道射手字段。

App11 封套和命令布局不变。LAN53 在握手时拒绝旧模拟协议。

## 验证

新增 CTest 为 `ra2.native_crew` 和 `ra2.native_crew_assets`，实际 App 入口为 `--native-crew-regression <输出目录>`。修改前同一真实登车/射击夹具为 6 个控制通过、4 个机制失败，修复后 10/10。单光束身份伪装探针原先 2 个控制通过、1 个机制失败，修复后 3/3；黑幕侦察探针原先 2 个控制通过、2 个机制失败，修复后 4/4。首轮全量的 154/156 失败日志保留。

最终 Release 非性能全量 **156/156，1552.37 秒**；ASan 相关 **27/27，846.46 秒**。两种构建各通过乘员 **108**、实体时空 **149**、IFV **140** 和侦察 **22** 条断言。实际专项保存 **132 对逐字节相同**，包含 42 对乘员、60 对时空及 30 对 IFV；收集器排除早期试跑留在审计目录中的旧文件名输出。

七局继续使用原固定观察窗口：**六局自然结束，五局通过全部严格条件**。英国/尤里 8527 tick 自然结束，但英国出兵数为零，经济检查与退出码 1 保留。YR 八人种子 1701 在原 360000 tick 内仍剩两家、没有结算，退出码 1 保留；355952 tick 仍有一家败北，尚未认定它是全局冻结。七局 55 个定期实际 App 检查点均精确，来源类型、资金和保存检查通过。七局更新完成边界的持续光束峰值均为零，不能充当 Temporal 的自然实战覆盖。

自然局与跨构建续跑是并发功能检查，其耗时统计不代替独立性能验收。33 个真实 App 输入在 0/120/3000/5000 tick 产生的 **264 对** World60/App11 保存跨构建逐字节相同，连同专项共 **396 对**。其中前 18 个历史输入的 **144 对**，仅去掉关闭的 CREW 块并还原格式标识后，与上一 Temporal 批次相同。最后一个输入是实际未结算海岛残局，只验证续档一致，不能把额外续跑计作延长后的自然验收。

所有已知功能和编译进程结束后，串行既有性能 **7/7，58.31 秒**。它不代替冷态、真实主循环、整局、GPU、人工或跨机器验收。**11028 个冻结输入零变化**，606 份修改前副本和上一批 1941 份封存产物保持相同。完整索引为本地 `review_out/crew-temporal-20261118/validation.json`；该批封存为 `closed_with_limits`，整体四阶段目标继续进行。
