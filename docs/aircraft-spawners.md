# 舰载机、反潜机槽位与整备

当前融合对局、RA2 来源包和 YR 基础来源包已接通 CARRIER/HORNET 与 DEST/ASW。影片按用户要求排除。普通飞机移动校准及完整来源包菜单继续处理。

## 问题与来源

修改前的独立 Release 探针在三种规则中记录九项失败：17 生命的存储飞机被重新创建为 75 生命；两套来源包的对象身份也被替换；飞机在空中时按甲板库存补机，出现甲板 3 架加空中 1 架；实际返航又丢失生命及身份。原始记录保留于本地 `review_out/project-review-20261115/carrier-probe/red.log`，修改前程序另归档为 `carrier-baseline-ra2.exe`。

本地两个原始版本的 CARRIER 都是三槽，`SpawnRegenRate=600`、`SpawnReloadRate=150`，生成 HORNET，后者为 75 生命、一发弹药。原始输入保留于 `carrier-source-audit.json`。公开的 [YRpp SpawnManagerClass](https://github.com/Phobos-developers/YRpp/blob/master/SpawnManagerClass.h) 区分了停靠、准备、攻击、返航、整备和损失再生；[Phobos 的生成器说明](https://github.com/Phobos-developers/Phobos/blob/c783774ab9440a7d49976faab1d8ff551cac156d/docs/New-or-Enhanced-Logics.md#aircraft-spawner-customizations) 记录普通生成器默认的 20 帧出舱间隔及等待同波飞机的行为。这些提供状态模型和默认间隔依据，不能代替原版函数或实机逐帧校准。

原始时间按现有来源规则合同从 15Hz 转为项目的 30Hz：损失再生 1200 tick、返航整备 300 tick、逐架出舱间隔 40 tick。融合规则新增 `CarrierRegenerateTicks`、`CarrierReloadTicks`、`CarrierLaunchDelayTicks`，默认取这些值；三个字段参与有效规则摘要和配置导出。

## 当前行为

`world_aircraft.cpp` 为每艘航母保留固定槽位，`cargo` 仅保存真正停靠和整备中的飞机。

| 槽位状态 | 飞机资料 | 转移条件 |
| --- | --- | --- |
| 停靠 | 实际存储记录 | 接受攻击后进入本波出舱队列 |
| 准备 | 带出生代次的飞行实体 | 等待本波其他已排队飞机出舱 |
| 攻击 | 实际飞机、武器和弹药 | 弹药耗尽或收到召回 |
| 返航 | 实际飞行实体 | 追踪母舰当前位置并靠泊 |
| 整备 | 保留受损生命、经验和对象键 | 剩余整备时间完成后补满生命及弹药 |
| 损失 | 空槽与独立剩余再生时间 | 时间完成后新造一架，分配新来源身份 |

在途飞机持续占槽。出舱恢复存储的生命、经验、军衔、弹药、状态计时和原始对象键；已有飞机重新出舱不消耗新的来源生产序号。物理实体槽再利用仍递增出生代次。返航期间不恢复生命或凭空产生替代飞机。

移动母舰保留已出航的攻击任务；明确的 Stop 召回飞机。目标被毁或转为友军时取消攻击。母舰换主时，飞机转属并返航；控制器与飞机行动前都核对所有权。母舰销毁后清除槽位关系，剩余飞机在下一次单位更新按失去母舰处理；中间状态可存档，原编号重用不会收留旧飞机。

己方受控舰载机不接受直接玩家指令，不参与己方点选及框选；敌方仍可用实际防空武器攻击它们。未登记的飞机不能通过填写某艘航母的编号加入它。融合航母默认不再被动重新索敌，避免 Stop 后自动开始下一波。

## 驱逐舰反潜机

DEST/ASW 在 Scene20 / World51 / LAN34 接入同一状态机。原始驱逐舰只有一个反潜机槽，飞机为 30 生命、轻装甲、一发弹药，原始损失再生 400 帧、返航整备 150 帧，对应 800/300 simulation tick。融合配置的 `DestroyerRegenerateTicks`、`DestroyerReloadTicks`、`DestroyerLaunchDelayTicks` 参与配置导出和规则摘要。

驱逐舰针对 `Underwater=yes` 目标使用副武器生成器，对水面及陆地目标保留舰炮。来源槽保留原始 `ASWLauncher` 的 `Range=-2`、`AG=no`，仅在派发专用行为时计算有效范围，虚拟武器不产生直接伤害。ASW 使用原始 50 伤害、射程 3 的深水炸弹；炸弹可在飞机落舰后才命中。飞机只能攻击水下目标，原始心灵控制免疫也得到保留。舰船换目标、移动、归属变更、损毁和编号复用仍走固定槽位与代次检查。

反潜机使用实际 ASW VXL/HVA；驱逐舰出击后按 `NoSpawnAlt` 切换 DESTWO 空甲板机体，整备中的真实存储飞机恢复甲板外观。来源包和融合渲染都使用实际素材；这三份 HVA 在本地原始包中均为单帧。

连续出击检查还复现了空槽重置武器冷却：融合规则整备完成后多等 27 tick，两套来源规则多等 286 tick。独立探针和正式回归分别保留了三项失败。当前仅在真实成功出舱后设置副武器冷却，保留成功发射的最短间隔；三个版本都在整备完成的同一 tick 重新出舱，并复用已有来源身份。独立前后记录为 `asw-cadence-probe/red.log` 与 `green.log`。

ASW 原始选中、移动、攻击和反馈语音字段均为空，语音库仍需要一个完整的空配置。生成器现已输出该项；仅改变语音 manifest 与来源报告，597 段已有 WAV 文件逐字节保持。原始 Osprey 起降音效仍列为后续核对项。

## 存档与兼容

World50 在 World49 后追加有长度尾标的飞机状态段，保存控制器开关、母舰/目标/飞机的编号与代次、固定槽位、出舱队列、整备和再生剩余时间。计时参数在创建控制器时冻结，并随对局保存；可变状态全部参与 checksum。读取检查容量、重复飞机、存储记录对应、原始类型、代次、状态与计时边界。

Scene19 导出不可变的 `NativeAircraft` 定义，禁止舰载机与导弹角色重叠，也不允许有载机容量的来源航母缺少控制器资料。解析失败不替换已有定义。App10 与原版地图 Scene16 保持。LAN33 因新航母模拟而更新，命令包布局保持；大厅当前仍只开放融合规则。

当前 Scene20 使用 `NativeAircraft` v2 标注发射槽、反潜限制和空甲板外观，并核对 DEST/ASW 类型和副武器语义。World51 在 World50 后另存 ASW 行为开关；旧 World50 保留航母控制器并关闭新的驱逐舰行为，旧 World49 及更早版本继续关闭现代舰载机控制器。实际 World50/Scene19 应用存档已归档，兼容测试比较完整 checksum 并继续模拟。当前协议 LAN34 沿用命令布局，在版本握手阶段拒绝旧模拟版本。

World49 及更早快照恢复为历史舰载机行为；继续读取 Scene17/18 的嵌入规则，不从当前安装的 Scene19 文件替换。实际 World49/Scene18 应用存档另归档为 `legacy-world49-scene18.sav` 并验证续跑。旧程序会拒绝新的 World50/Scene19。

## 验证范围

```powershell
ctest --test-dir build -C Release -R '^ra2\.(aircraft_spawners|rules_profile|state|app_state|entity_identity|attack_move|net_protocol)$' --output-on-failure
```

`ra2.aircraft_spawners` 在三种规则下使用真实攻击和移动命令：三机出舱、等待同波、移动母舰时继续轰炸并返航、实际防空击落、受损整备、按原始期限再生、母舰换主/销毁、编号复用、未登记飞机拒绝、来源生产序号耗尽、多个阶段续档、非法存档及双分辨率点选/框选/绘制。展示视野只在渲染副本打开，不修改受测对局的正常视野。

航母专项 61 条断言通过，覆盖三种规则；产品代码的 ASan 十项通过，178.04 秒，未报告内存错误。全量首轮 126/133，1077.82 秒。七项失败收敛为六处测试适配：四处损坏存档检查漏算新增尾部，两处旧版快照比较没有设置历史舰载机模式；通关组合又调用了补给箱损坏检查，因此同时报错。

随后仅调整这六处回归夹具：v47 之后的尾部统一通过长度尾标定位，旧快照仍比较完整 checksum 和实际续跑。相关 Release 13/13 通过，110.91 秒；追加 ASan 六项通过，343.88 秒，未报告内存错误。没有第二次完整 133 项全绿运行，不合并分批成绩为一次全量通过。

最终冻结 1213 项源码、测试、配置及来源包美术；与首轮全量相比只改变上述六个回归文件，模拟源码和来源包不变。两种构建的实际应用存档逐字节相同，316969 字节。完整日志、范围、二进制/文件哈希及后续 ASW 六项失败记录为本地 `review_out/project-review-20261115/carrier-validation.json`。该清单不覆盖每张基础贴图、原始 MIX、音频、缓存或用户文件。

当前 ASW 专项为 87 条断言，覆盖融合、RA2、YR 三种规则及实际 World50/Scene19 旧应用存档。包含实际普通攻击、50 伤害深水炸弹、防空击落、移动母舰、目标切换、整备/再生、连续出击、来源身份、非法定义及损坏存档。两个分辨率各输出实际出击与甲板画面。

ASW 首轮完整 Release 为 131/134，1147.24 秒；三个失败均来自缺少 `Unit.asw` 空语音配置，包括依赖语音加载的展示回放。全量后仅改变两份 C++ 文件：修复连续出击的空槽冷却，并新增对应断言；音频生成只改变 manifest 与来源报告。最终相关 Release 18/18，68.08 秒，覆盖三项原失败；最终 ASan 13/13，264.05 秒，未报告内存错误。未再次运行完整 134 项，不把分批结果称为一次全量通过。

最终冻结 1923 项输入，比完整回归时的 1324 项增加了整套单位语音元数据与 597 段 WAV 的哈希。冻结范围内两份 C++ 的变化明确列出，597 段 WAV 均与生成前相同；两种构建的实际应用存档逐字节一致，为 324984 字节。当前证据、原始规则、独立失败/修复日志及冻结输入分别见本地 `asw-validation.json`、`asw-source-audit.json` 和 `asw-final-inputs.json`。
