# 原始遭遇战 AI 接入方案

当前遭遇战仍使用普通 `SkirmishAI` 策略；原始任务编队执行器主要服务已导入战役。乘员选枪修复与这项工作独立，见[本批实现](crew-weapon-selection.md)。以下是已完成的来源审计和下一步实施范围，不是全局 AI 已接通的声明。

## 全局引用图导出已完成

`tools/ra2pack/source_ai.py` 现可从同版本原始 MIX 导出独立 JSON 包，并绑定现有可执行规则包的 SHA256。它保留完整原始 INI 字段、脚本占用槽位、队伍标志、国家限制、三档难度和全部 32 字节比较块，另解析编组／脚本／队伍／触发器引用及实际 NativeType。全局声明默认启用和显式启用列表分别保留，不把战役本地缺省策略套到全局声明。输出明确为 `runtimeEnabled: false`，尚未成为游戏加载入口。

```powershell
python -B tools/ra2pack/source_ai.py ra2 --profile assets/rules/profiles/ra2.ini --output review_out/ra2-ai.json
python -B tools/ra2pack/source_ai.py yr --profile assets/rules/profiles/yr.ini --output review_out/yr-ai.json
```

导出器检查同版本来源、规则哈希、引用完整性及编组／条件／建筑脚本所需实体。YR 可选唯一的 `expandmd01.mix` 覆盖；多份候选拒绝导出，也不会退回 RA2 数据。本机两版完整图分别为 81/52/103/107 和 132/88/163/165（编组／脚本／队伍／触发器），实际所需类型均能绑定。原建筑注册表重复声明 `NAPSYA`，且存在没有独立定义节的类型；声明保留，重复 ID 复用首个类型槽，未定义条目仍占槽。原列表键从 1 开始，脚本类型索引从 0 开始，二者不能混用。

RA2 数据本身包含指令 58，不能因为 [FA2sp 的脚本说明](https://github.com/secsome/FA2sp/blob/master/DOCUMENT.md) 将其列为 YR 指令就删掉。原始 `Reinforce` 等队伍标志也原样保留，导出不把它们转换为免费增援或假定执行器已经支持。`tests/source_ai_test.py` 覆盖完整原始图、重复导出、缺失引用、版本隔离、比较字节、脚本缺槽与非法输入。新增 9 项测试通过，现有来源规则和战役 AI 资产检查通过；本批没有更改 C++、规则资产、存档、网络或对局行为。

证据位于 `review_out/native-global-ai-graph-20261118`。首轮把原建筑列表当作每项必须有独立节而拒绝导出，以及首轮测试混淆列表键 241 和数组位置的失败均保留；修正后两版导出通过。测试仍报告 `ra2lib.py` 既有的名称表文件未关闭 `ResourceWarning`，本批未扩展到该文件。

## 条件 5–7 的新增原 RA2 校准

同一原始 `GAME.EXE` 的三个子程序新增 **944/944** 隔离样本通过。条件 5/6 扫描第一房主参数的超武列表，选首个对应类型，要求原偏移 `+0x55` 标志为真，并比较剩余充能比例与 `1 - 来源百分比`；它们不是简单的“充满才成立”。静态规则读取指令另确认该百分比写入来自 `AIMinorSuperReadyPercent`。样本覆盖运行／暂停计时、阈值边缘、空列表、类型缺失和首个同类禁用的情况；`+0x55` 的结构字段名称尚未独立确认。

条件 7 读取字符串 `Civilian`，枚举房主并比较其类型偏移 `+0xbc`，选最后一个匹配者后读取该房主的对象计数，而不是简单把所有 `player == -1` 的对象相加。维护者的 [HouseTypeClass 声明](https://github.com/Ares-Developers/YRpp/blob/61d0887eb6040cfb36af16d592e9770ceae4dfb2/HouseTypeClass.h) 将相应结构字段命名为 `SideIndex`，与 `Civilian` 阵营解释相符；独立 YR 机器码尚未校准。接线前仍需确认本项目中 Civilian／Mutant 的持久身份，不能只用中立显示状态替代。

这 944 项执行的是隔离的原 RA2 谓词，使用合成房主、计时器、类型虚函数和计数接口；未执行原游戏入口、完整触发调度器、目标知识、实际超武或独立 YR。此前 782 项计数／全局启用校准另保留，不能把合计样本数当作完整游戏复刻验收。

首轮新增校准将查询字符串预期为 `Neutral` 而失败；读取原始字节确认实际为 `Civilian` 后修正的是校准器断言，没有修改原程序或生产代码，首次失败日志保留。
