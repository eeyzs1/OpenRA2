# 原版桥头小屋、修桥与净空规则

本批接入工程师通过桥头小屋恢复原始跨度，并补齐上一批遗漏的原版净空和任务开关。后续已接入 [原版闸门开合](native-gates.md)。原版第一关仍未开放为可通关战役：部分基地交接已由原始事件执行，完整坍塌和任务仍未完成。

## 原始数据与行为

本机核心 `rules.ini` 中 `CABHUT` 有 `BridgeRepairHut=yes`、`Immune=yes`、`Strength=2000`。它是修桥入口，不能当作普通可占领民房。原版手册描述工程师进入修桥小屋修复桥梁，工程师被消耗。参见 [Westwood 原版手册镜像](https://manualzz.com/doc/24314810/westwood-studios-red-alert-2-user-manual)。本批没有借用 OpenRA 的低桥传播时序作为原版高架桥时序。

本关两座小屋 `(80,48)`、`(84,48)` 都连接 `(82,51..55)` 的五段桥。另一座 `(62,57..60)` 的四段桥保持独立。连接按源桥轴、相同原始高度和桥头邻近关系建立，已核对本关；任意自定义地图的复杂交叉连接仍未按原机校准。

Scene v3 增加原始小屋属性、单位 `TooBigToFitUnderBridge`、桥段 `OriginalHeight` 和场景 `DestroyableBridges`。桥梁蓝图保留源对象键、位置、类型、朝向、原始帧和高度，随源场景保存、读档后重建。修桥按源键找现存桥段或重新创建，不能复活已经被其他单位占用的旧实体编号。

## 修复流程

右键小屋发出明确的 `RepairBridge` 工程师意图。模拟端先确认连接、损坏及可达入口，工程师到相邻入口后才恢复该跨度的原始覆盖物、全生命和桥面通行，并消耗一名工程师。它不会转变成占领小屋，也不会修复另一座桥。

完整桥梁、不可达入口、失效小屋和被其他覆盖物替换的位置均拒绝修复，保留工程师。两名工程师先后抵达同一跨度时，只消耗实际完成修复的一名。桥下净空不足的单位会阻止修复；能容纳的小型水面单位可以留在桥下。前者是当前工程的一致性限制，原版在该边界上的拒绝、挤出或伤害细节仍待实机校准。

**入口的历史限制与后续进展。** 两座小屋被沙袋、悬崖和 `GAGATE_A` 闸门围住；修桥批当时尚无开门机制，夹具先验证不可达，再以真实伤害打开闸门。后续闸门批已替换该夹具：保留完整闸门，在停战联盟下实际等待开门、穿门并修桥。源地图与修桥距离均未改。原图门开局属于非友好房屋，原作者的归属交接仍须由事件链执行；不能把取得权限后的机制验收当作本关已通关。

## 净空与任务开关修正

上一批未执行净空标志，错误地放行了台风潜艇。现在读取原始 `TooBigToFitUnderBridge`：台风潜艇等受限单位不能进入下层桥格，海蝎等允许通过的小型单位可以。路径搜索、编队连通区域、实际跨格、让路、交互、装卸载、传送落点和工厂出口均使用单位的净空条件，鼠标光标也读取同一能力。旧双层专项改用海蝎，并增加受限潜艇拒绝/调整落点检查。

第一关原始 `[SpecialFlags] DestroyableBridges=no` 禁止普通火力破坏桥梁。该标志属于场景运行状态，不是桥型永久免伤：初值来自场景，运行时可以改变，并单独保存、校验。直接的地图/脚本移除仍可使桥段失效，为后续原版“断桥”动作保留入口。小屋自身的 `Immune=yes` 另按原始类型执行。

## 存档与模块

修桥批以 World v33（`RA2WRLDX`）增加修桥意图并保存当前桥梁破坏开关；后续闸门批写入 v34（`RA2WRLDY`），事件批写入 v35（`RA2WRLDZ`），当前 [队伍脚本批](native-teams.md) 写入 v36（`RA2WLD36`），继续读取历史格式。应用封套仍为 v10，兼容 v9/v8/v7。兼容夹具另覆盖 v10 封套中的旧 World v31、v32、v33、v34、v35。当前 LAN 模拟协议为 v12；`Repair.b=1` 表示修桥，0 保持普通建筑维修，其他值在修改订单前拒绝。

`world_bridge_repair.cpp` 管理派生跨度、查找、修复和工程师到达；`world_bridges.cpp` 保存分层及破坏开关；`world_native_scene.cpp` 重建来源数据。普通新对局会清空上一场的桥梁蓝图、分组和破坏标志。表现缓存不进入 World 校验。
