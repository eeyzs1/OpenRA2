# 独立支援与出生老兵经验

本批接续四阶段审查方案的第二阶段。普通来源包升级为 Scene30 / NativeProduction4，状态为 World56 / App11，模拟协议为 LAN46。旧 World55 与更早快照保留共享支援槽及原有出生经验行为；本批仍不代表完整复刻完成。

## 已修正的实际行为

此前实际渗透兵营、付费生产的 GI 以军衔 1、经验 0 出厂，击杀价值 1000 的间谍后仍停在军衔 1。新游戏在工厂发放老兵加成时同步设置经验边界：GI 从 600 起步，该次真实击杀后达到 1600 并晋升精英。复制中心的免费副本、舰船以及停在机位的单位共用工厂初始化路径，来源 `Trainable=no` 工程师继续不晋级。该修复不倒改旧快照里已经保存的经验。

支援原本只有 `paradropCharge` / `paradropReady`。修改前的实际命令探针另复现三项失败：苏军缴获美国空指部后收到八名动员兵，使用伞兵清掉其他支援的冷却，随后无法使用本应独立充好的侦察机。现在四项支援各自保存充能与就绪状态，并有独立按钮和指令选择器。

| 支援 | 原始冷却 | 载荷或作用 | 来源 |
| --- | ---: | --- | --- |
| 通用伞兵 | 7200 tick / 4 分钟 | 盟军 6 GI、苏军 9 动员兵、尤里 6 新兵 | 科技机场 CAAIRP |
| 美国伞兵 | 7200 tick / 4 分钟 | 8 GI，缴获后也保留该身份 | AMRADR |
| 侦察机 | 7200 tick / 4 分钟 | 独立侦察指令 | YR NARADR |
| 心灵揭示 | 7200 tick / 4 分钟 | 独立揭示指令 | YR NAPSIS |

RA2 来源包只提供前两项；YR 基础包提供四项。融合规则使用相同的独立状态接口，保留自己的国家和建筑准入，通用机场的中国分支投送六名解放军。

这些时间、载荷及 `IsPowered=false` 来自本地原始规则。不会把雷达建筑的 `Powered=true` 当作它所提供支援的 `IsPowered`：原始这四项在停电时继续充能。显式设置为需要电力的规则会暂停充能和使用，但保留已充好的状态。

销毁、出售或易主会重新计算能力来源。失去最后一个科技机场仅清掉通用伞兵槽；美国空指部和其他支援保持各自状态。存在第二个有效来源时保留充能；同一帧重建最后来源也不会恢复已清掉的就绪状态。

## 调用和保存

`world_support.cpp` 负责来源、冷却、准入及释放；`world_support_save.cpp` 保存四槽与行为开关，使用带长度的追加状态块。World56 仍由既有 App11 容器承载，读取时不重写保存的充能。`world_veterancy.cpp` 统一处理工厂出生经验。两个行为开关进入确定性摘要，禁用时保留历史摘要路径。

`Game` 的共用生产网格按实际来源显示独立按钮，分别从原始 SHP 提取图标：RA2 来自 `language.mix/cameo.mix`，YR 专属图标来自 `langmd.mix/cameomd.mix`。每个图标记录原始来源、SHP 与 PNG 摘要；并使用原始 `cameo.pal`。目标选择、取消、真实地面点击与两个实际显示尺寸已接入专项验证。

`World::Cmd::Paradrop` 的 `a=1..4` 明确选择通用伞兵、美国伞兵、侦察机、心灵揭示，`a=0` 保留默认伞兵接口。LAN46 的真实命令解码器校验该范围。Lua 使用 `ra2.supportReady(player, type)` / `ra2.orderSupport(player, type, x, y)`，其中 `type=0..3`；旧 `paradropReady` / `orderParadrop` 继续可用。新的 Lua 写接口也受到存读档只读阶段的约束。

AI 通过自己的已观察建筑记忆选择投送点，不从隐藏世界实体直接读取敌方基地位置；侦察类支援可用于探索地图中部。已观察目标下可分别使用两种伞兵，不相互消耗冷却。

## 验证范围

永久入口为 `ra2.source_support` / `--source-support-regression`。覆盖实际充能、停电、四项连用、两种来源的真实工程师缴获、三阵营原始载荷及融合分支、最后来源与重建、真实 HUD 点击和取消、双分辨率、真实 App11、损坏拒绝、AI 情报约束、Lua 及真实 TCP 指令和越界拒绝。

同时扩展 `ra2.source_economy` 到 50 条断言，覆盖实际老兵/克隆出生经验、真实击杀晋升、舰船经验及保存恢复；原有 77 条规则一致性断言继续保留。历史兼容另外使用从真实第 18000 tick App11 原样提取的 483699 字节 World55，读取、再次保存和 180 tick 续跑保持一致；来源摘要保存在本批证据目录。

Release 首轮全量为 151/153，1367.21 秒；两项失败来自旧 v20/v21 工程师和维修测试的预期 World 未关闭新增行为开关，共三条历史兼容断言。仅修正两处测试的预期状态，保留原始旧格式写入器、实际读取、工程师意图检查及维修续跑 600 tick。首轮之后模拟代码、来源导出器和资源未再变化；两项失败日志原样保留，没有把该轮记为全绿。

修正后相关 Release 10/10（32.31 秒）、ASan 35/35（1032.28 秒）通过，均无失败或跳过，未报告 ASan 内存错误。两种构建各执行经济 50、支援 68、一致性 77 条断言；来源导出器重新生成四组规则并通过原始文件对照。本批没有在修正测试预期后再跑第二次全量。

首轮和最终两组验证的 10744 项冻结输入均未变化；两组清单之间仅有上述两个测试文件及重新链接的两个游戏程序不同。14 组实际经济/支援 World56/App11 存档在 Release 与 ASan 间逐字节相同，历史 World55 夹具与原程序摘要保持不变。准确选择集、原始日志摘要、变更范围与保存对照见 `review_out/support-20261117/validation.json`。

完整 Release 内的四局普通来源对局分别在第 72735、80724、104143、83171 tick 自然结算，40 个 App11 检查点读取、重存及继续模拟保持一致。这是 RA2/YR 双人陆地/岛屿各一局，未把它计作 ASan 自然对局矩阵、阵营平衡结论或完整整局帧率测量。
