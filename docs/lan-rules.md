## 当前握手

客户端连接后由实际大厅轮询发送 Hello，携带版本、规则选择、国家、颜色和规则摘要。主机先验证 Hello；点击开始后发送带规则选择、种子、选项和摘要的 Welcome，进入等待确认状态。客户端完整校验后回送 Ready，主机核对种子和当前规则后才发送 Start 并创建新世界。客户端也在 Start 时再次核对规则。

四种握手包分别限定角色和阶段，检查完整长度、种子与枚举。拒绝包只携带有界原因码；界面显示版本不同、规则不同、无效规则数值或握手失败。当前游戏世界在拒绝时保持原状。发送拒绝原因的一端继续驱动网络输出，等待对方读取并关闭，或由玩家返回。命令帧和运行中校验机制继续沿用现有锁步路径。

双进程自测与界面调用相同的 Hello、Welcome、Ready、Start 方法；自测等待有超时，不再绕过确认直接开局。旧 LAN26 程序不能参与此协议。

## 摘要范围

`data_fingerprint.cpp` 对最终生效的人类双人联机资料计算 SHA-256，当前摘要格式为 2。按固定顺序写入显式标量、字符串和计数，忽略内存地址及结构体填充；相同精英武器换一个存储地址不改变摘要，等价的正负零按同一值处理，非有限浮点数在开局前拒绝。

覆盖全局经济、生产、军衔、动画持续时间等模拟参数，全部单位、建筑和超武资料，普通/精英/对空/部署及特殊武器，弹头倍率与范围参数，以及最终生效的弹道定义、桥接和后备弹道。弹道表按键排序，已被覆盖的旧条目不计入。`Weapon.Proj` 和解析后的弹道类型标识还选择模拟效果，因此参与摘要。

单位/建筑显示名、音效名、图片、文件安装路径、注释和条目顺序不参与。弹道类型标识与这些显示资料不同，不能排除。只影响 AI 的配置及未替换基础表的独立变体也不参与：当前联机使用两个人类玩家、程序生成地图，并停用 Lua 和 AI；替换基础表的 INI/CSV 结果已经包含在有效资料中。以后扩大联机内容范围时应同步扩大此合同和协议版本。

## 验证与模块

`core/sha256.*` 负责字节摘要，使用 [NIST Secure Hash Standard](https://www.nist.gov/publications/secure-hash-standard) 的 SHA-256 定义；`ra2.hash` 检查标准向量、独立的 Python hashlib 填充边界答案和分段写入。`ra2.rules_fingerprint` 在无窗口进程中检查规则变化、地址独立性、重排、图片与无效数值。

`game_net_handshake.cpp` 负责握手状态机；`game_net.cpp` 保留锁步与大厅调用。`ra2.net_protocol` 使用实际 TCP 检查自动 Hello 和等待 Ready，遍历每种消息的全部截断前缀，检查尾随字节、旧版本、错误摘要、错误阶段、握手中途改规则及拒绝原因，并输出中英文、两分辨率的实际界面图。

`ra2.net_rules` 运行 15 组本机双进程场景。生命值、经济、普通/精英/对空武器、弹道数值与类型及 CSV 差异必须在双方 tick0 拒绝；无效浮点数以独立原因拒绝；同值重排、CSV 最终覆盖一致、显示和图片变化应完成 tick360 且校验一致。测试会保留逐端日志和结果 JSON。
