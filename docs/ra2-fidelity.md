# RA2 / Yuri's Revenge 融合复刻规则基准

本文是 OpenRA2 的玩法契约与差异清单，不是“已经实现”列表。目标是先让遭遇战闭环可验证，再逐项逼近 **Red Alert 2 1.006** 与 **Yuri's Revenge 1.001**；共和国之辉、中国阵营及自制战役作为明确的融合扩展保留，不反向定义官方规则。

内置遭遇战 AI 为自制融合实现：出击门槛的波次增量在六波后停止增长，只有合法接受的地面攻击计为一波；不兼容目标可改攻已揭示的兼容目标，防空根据当前合法单位表与可见空中威胁补充。中国高科使用现有融合规则允许的天启作地面防空，尤里按现存狂风/磁电数量维持约 3:1 的输出与支援配比，避免奇数波停滞后只生产支援。这些是本项目的决策策略，不作为官方原版 AI 行为的一致性声明。

移动占位采用本项目的每格最多三名步兵、地面车辆独占模型；静止非盟友/部署占用按容量参与路径阻挡，可协作空闲友军与有待执行路径者保留让行。当前重甲车辆碾压检查区分阵营、无敌和部署状态，完整类型专属 Crusher/Crushable 元数据及英雄边界仍待补齐。

相邻窄格内的移动单位互占下一格时，按稳定实体 ID 顺序尝试临时退让；保留正在前往会车点的等待路径，仅重复等待点本身已被占住时允许替换。退让规划把另一单位的最终停车点视为未来障碍，沿普通移动路径完成，保留原终点、攻击移动状态和排队命令；警戒、定身及非盟友不参与。通道调度不得假定未参加穿行准入的本地停车单位会让开，退让规划按其实际硬占用处理。反向退让请求按 tick 和实体 ID 每八 tick 错峰重试，避免原地失败双搜索持续抢占共享预算；无需额外随机数或存档计时字段。普通空地停车也使用保留路线和其他单位目标的连续让路，移除旧的邻格瞬移推让。AI 仅在匹配设施有已完成订单时，以实际占用寻找清口路线；密集队列先挪队尾，受保护或非己方单位不会被强制挪走。单位实际插值被阻挡时释放未能使用的本 tick 下一格预约，避免先占预约却无法前进的单位反过来困住能够驶离的同伴。通道准入本身造成的入口互锁也可触发相邻互占下一格的让行，按 tick/实体 ID 每八 tick 错峰请求；通道内已开始的等待点退让路线保留到完成，暂缓新进入者，避免门控在每个 tick 把部分位移改回原方向。该调度属于本项目交通模型，不宣称与原版引擎的局部避让算法一致。

紧凑路口（最多 64 个相连开阔格，连接至少三个不同窄道口格）与相连车道共用准入区域，避免四向流各自占满出口。较大的等待场保持独立；物理上的开阔格仍可供让行。路网空闲且当前方向无人等待时可提前交接，不空耗整段时间片。分类不会因为先查询开阔格而漏合并路口。以上为本项目的确定性交通协调实现，不是原版寻路规则或全路网无死锁的声明。

集结点是当前融合生产交互：兵营、重工、船厂、空指与复制中心支持设置/清除，新单位按自身通行域选择落点。精炼厂保持自动采矿，不显示无效的集结能力；新空指默认停机，有集结点时新机起飞。旧存档的非负空指集结坐标会按保存值生效（旧默认与手设位置无法区分），清除后可恢复停机。采矿仍采用现有 DockUnload=(3,1) 与卸矿范围近似，返厂会选择可达卸矿位置或备用己方设施；不把这些工程边界修复宣称为官方停靠公式已校准。

## 基准、口径与状态

尤里新兵 `PsychicJab` 已与心控弹头分开：使用新增 `SAFlame`，保留心控单位的 `Psychic`。本轮可核对的本地证据为 `tools/ra2pack/game/ra2md.mix` 内 `localmd.mix/rulesmd.ini`（SHA256 `06761dd7f714e7d9400216ec3c06109ec5c1461f6a0727be7401eb9d8b0f6d05`），其中 `PsychicJab.Warhead=SAFlame`，11 装甲倍率为 `1,0.8,0.8,0.5,0.25,0.25,0.75,0.5,0.25,1,1`。这是本机 YR 基础包规则证据；未找到本机 `expandmd01.mix` 的对应最终补丁规则，不将本项表述为完整 YR 1.001 校准。其他弹头矩阵未作本轮调整。

AI 的地面部队跨海投送为自制策略：有独立陆块时配置运输船，现有步兵与可装载战车通过真实登船、移动、卸载指令执行运输；登陆队按可见敌人与所在陆块的迷雾继续侦察/作战，运输船返航。通用两栖运输船按本地 `rulesmd.ini` 的 LCRF/SAPC/YHVR 校准为尺寸总量 12、乘员尺寸上限 6；普通步兵尺寸 1，普通战车 3，MCV/天启/磁电/主脑 6，狂兽/恐怖机器人 2；IFV 尺寸上限为 1。载矿量、生命、军衔、冷却、箱子增益和 IFV 等载具内乘员随货舱保存，货舱内计时效果继续衰减。World 当前格式为 v25（RA2WRLDP），嵌套载员入校验。仍与活动心控/寄生实体相连的单位暂拒登船，避免装载清除关系造成状态丢失；这是当前工程限制，不作为原版兼容规则声明。高射炮车仍为 `Cargo=0`，与本地原版 HTK 的 Passengers=5 不同，其他运输车型的尺寸兼容仍待校准；不把两栖运输修复宣称为全车型完成。

船厂的当前出厂模型为脚印共边的水面出口：优先南侧中央，再按固定顺序尝试其他紧邻边缘，不跨越阻挡到远处生成。生产与 AI 清口共享这组位置；全部边缘封锁时保留已付款完成项，开放任一出口后只释放一次。陆上工厂保留固定门口。四岸方向与保护/封锁有固定回归，此工程模型不等于原版全部出厂偏移和动画的逐项校准。

资源外观按剩余比例选择八档晶簇显示，并使用与采空后相同的 Rough 底材。当前实现从已有 TIB/GEM PNG 中保留完整可见晶簇及其边缘像素，属于表现近似；尚未逐矿量等级校准原版 SHP 帧。此调整不改储量、产值、再生规则或采矿速度。

基准优先级：

1. RA2 与 YR 英文手册描述玩家可观察到的行为。
2. 最终官方补丁：RA2 1.006、YR 1.001；补丁行为覆盖首发版手册。
3. 对数值、前置、装甲/弹头和引擎标志，以最终版 `rules.ini` / `rulesmd.ini` 为准。YR 1.001 的规则应从 `expandmd01.mix` 提取，不能误用 `localmd.mix` 中的 1.000 版本。
4. 本仓库的 `assets/rules/rules.ini` 是 OpenRA2 的扁平化自定义格式，不是原版规则文件；只能代表当前实现目标，不能作为官方证据。

状态标记：

- **一致**：核心玩家可观察行为已接通；数值仍须用自动化断言锁定。
- **融合**：有意偏离官方，必须保留本节说明或由显式选项启用。
- **部分**：存在可用主路径，但缺少关键边界、数值或专属能力。
- **缺失**：只有名称/数据，或没有可玩的逻辑。
- **待证**：仅从代码静态审计无法证明，须加确定性测试或实玩场景。

## 当前规则文件的已知偏差

以下差异可直接由 `assets/rules/rules.ini` 与代码确认，不能标成“官方数值复刻”：

- 核子反应堆 `Power=2000` 已对齐参考表；熔毁有瞬时 AoE + 残留波（非官方辐射场瓦片）。
- MCV 成本已对齐官方常规值 3000；建造厂仍为项目表值，需与最终 rules 核对。
- 已提供 11 类装甲/弹头矩阵，主要单位/防御主武器在 `rules.ini` 已标注 `Weapon.Warhead`（与代码 `withWH` 对齐）；未标者仍走 Legacy `VsInf/VsVeh/VsBld`。
- 官方战役原型轨：盟军 oa01–03 + 苏军 os01–03（`Track=1`）；完整 12+12 地图/FMV 仍缺。
- 当前 `BuildTime`、`Speed`、`ChargeTime` 使用项目自定义逻辑帧语义，不能直接与 rules/rulesmd 的分钟、帧或引擎倍率字段逐字比较。
- 尤里奴隶经济采用可部署 `SlaveMiner` + 自动产奴近似，不是完整官方奴隶矿场建筑语义。
- 当前中国共享幻影坦克、V3、天启、基洛夫、铁幕和核弹等项目是融合配置。
- `GameRules` 的低电、军衔、箱子间隔、矿再生等字段已有主路径接通；仍需逐项核对全部调用点。

在引入原版数值时，应保存一份“来源字段 → OpenRA2 单位换算 → 自动化期望”的机器可读映射，禁止直接凭中文攻略或记忆修改数值。

## “可玩遭遇战”验收门槛

首轮交付只要求标准 Battle 闭环，但以下各项必须可失败地自动验证：

1. **四阵营开局**：盟军、苏军、尤里、中国各从一辆 MCV 在远离其他建筑的合法地形展开。
2. **经济闭环**：电厂 → 精炼厂和赠送矿车 → 持续采矿卸载；资金不为负，宝石高于金矿，阵营矿车行为正确。
3. **生产闭环**：兵营、重工、雷达/空指、高科、海军和超武前置合法；扣款、暂停、取消、出口堵塞均不丢钱或吞单位。
4. **战斗闭环**：地面、空中、海军可获取合法目标；目标死亡后清理引用；拥堵可重寻；运输可装卸。
5. **电力与超武**：低电状态一致；每阵营至少一项超武能充能、选点、生效、重置；Chronosphere 使用双阶段目标流程。
6. **胜负闭环**：仅当对应规则的失败条件满足时判负；最后存活阵营获胜且对局停止。MCV、采矿车、受控单位和联盟均有边界用例。
7. **长局稳定性**：固定 RNG 的至少 20,000 tick 对局无卡死、负资金、永久无效队列、悬空目标或无法结算。
8. **证据要求**：smoke 的每个 `expect` 必须影响退出码；跳过场景不是通过；关键矩阵项必须有直接驱动 `World` 的确定性测试。
