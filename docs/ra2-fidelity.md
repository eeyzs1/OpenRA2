# RA2 / Yuri's Revenge 融合复刻规则基准

当前普通RA2为Scene63/Production11。建造厂的出售按钮和默认Delete现在执行现金出售，MCV打包保留独立部署入口及选项；人类返1500，其他普通房屋返3000。旧Scene62及更早继续原建造厂拒售/输入打包策略。依据是tests/fixtures/ra2-conyard-sale-reference.json中的32组原版入口、任务前缀和打包查询。

Scene62引入来源出售返款及完成门：普通建筑出售在既有拆除完成边界入账：精炼厂返300，非零Soylent优先，其余按本地原版人类/其他普通房屋策略计算，HP不缩减返款。原版268组隔离检查与当前真实命令流程分别验收，见`tests/fixtures/ra2-building-sale-reference.json`。本项目现有默认第41tick拆完，不宣称原版完整动画/输入时序一致；幸存乘员与储矿清理另属未完成范围。Scene61及更早、YR/融合/作者场景保留旧即时返款。

Scene61引入来源扳手维修：建筑扳手维修按原版默认每28逻辑tick补8HP，采用逐步整数费率及原版舍入；尾笔按完整一步收费，资金不足关闭维修。Scene60及更早、YR和融合保持旧策略。World64..76、App11/12和未发布LAN96没有新字段。原版55组隔离执行与当前真实指令流程的依据见`tests/fixtures/ra2-building-repair-reference.json`，完整鼠标/外围Building AI时序及人工实玩仍待校准。

本文是 OpenRA2 的玩法契约与差异清单，不是“已经实现”列表。目标是先让遭遇战闭环可验证，再逐项逼近 **Red Alert 2 1.006** 与 **Yuri's Revenge 1.001**；共和国之辉、中国阵营及自制战役作为明确的融合扩展保留，不反向定义官方规则。

以下差异表保留此前融合实现的审查口径，其中旧World格式、舰载机、来源规则、盖特等条目不能直接代表当前来源包。当前合同以[架构](architecture.md)和[规则包](rules-profiles.md)为准。当前普通入口默认经典RA2，接入两张原版遭遇战地图；矿车新局收益按原始25/50校准，旧场景保留原收益；基础坦克和盟苏矿车行驶时支持32朝向显示。逻辑转向ROT、停靠节奏、完整原版AI和全部战役尚未完成校准。来源包使用已识别的本地基础版，不宣称已经校准到最终官方补丁；影片按用户要求排除。

内置遭遇战 AI 为自制融合实现：出击门槛的波次增量在六波后停止增长，只有合法接受的地面攻击计为一波；不兼容目标可改攻已揭示的兼容目标，防空根据当前合法单位表与可见空中威胁补充。中国高科使用现有融合规则允许的天启作地面防空，尤里按现存狂风/磁电数量维持约 3:1 的输出与支援配比，避免奇数波停滞后只生产支援。这些是本项目的决策策略，不作为官方原版 AI 行为的一致性声明。

移动占位采用本项目的每格最多三名步兵、地面车辆互斥模型；Scene48的车辆接近可碾压步兵时允许暂时同格，其他占用继续硬挡。静止非盟友/部署占用按容量参与路径阻挡，可协作空闲友军与有待执行路径者保留让行。普通RA2 Scene47已读取本机原版`Crusher`/`Crushable`：矿车、光棱与幻影按原始资格碾压，动员兵的装甲不再阻止碾压，超时空军团兵、磁暴步兵及辐射工兵按类型免疫。部署大兵沿用本类型的可碾压标志，盟友、无敌、定身和跨层保护保留。旧场景、YR和融合规则维持原判定。Scene48在实际路径位移后按原版隔离执行测得的严格半格水平距离结算。车辆在转向、受阻或停止时不再提前杀死步兵；直线、斜线与两侧宽弯使用同一接触处理。同格目标用世代引用处理，死亡回调后重新验证。Scene47续档保留原触发时机。Scene49允许已有路径的步兵在共享原格内推进并离开，车辆保持原地，新格的车辆阻挡继续有效。原版隔离对照运行了11组已获准步行段，执行原始坐标提交；步速与斜步量化只作观测，本批未调整。Scene48旧现场保留原来的格内阻挡。Scene50在新行驶段建立时按来源PlayerScatter/IQ/Fraidycat规则预警；默认普通玩家步兵不自动移动，达到门槛的AI与精英格有原版例外，人工部署步兵仍不自动散开。普通移动令不被覆盖，Fraidycat按来源允许重选方向。邻格选择使用步兵朝向或格内偏移与随机偏角，不保证朝车辆反方向，也不保证一定逃脱。16组真实命令、80组原版落点对照与一组实际逃离核对这些边界；原始181组隔离执行见`tests/fixtures/ra2-crush-warning-reference.json`。Scene49及更早维持原行为。`ra2.crushing`覆盖实际移动、旧档与续档；原版完整帧调度、散开寻路/桥面几何、主动碾压、其他军衔能力和演出仍待校准。

接触碾压已区分于普通受伤倒地：车辆实际碾到步兵时直接移除，不再播放Die1，保留碾压声、单位损失提示和死亡回调。原版13组隔离执行运行了销毁登记、移出地图及排队删除；普通受伤和PlayAnim入口均无调用。完整地图/无线电清理、全局删除和声效播放是隔离夹具依赖，未据此宣称完整原版演出一致。原始证据见`tests/fixtures/ra2-crush-death-reference.json`。现有版本和模拟合同不变，普通伤害仍倒地，旧档中已存在的动画继续其剩余寿命。

Scene51另校准友军步兵后来进入已下达Drive路线并警戒的受阻反应。真实Move与Guard在Scene50中使灰熊、多功能步兵车原地停留600tick；原版正常Drive准入分支会在对正后要求该友军步兵强制散开，不依赖Crusher，默认人工控制大兵和部署大兵也可响应。原版平地准入和24组分支执行见`tests/fixtures/ra2-drive-blockage-reference.json`，通行底层和路径方向是明确供给的夹具依赖。项目复用邻格选择与正常移动/解除部署，不消耗步兵生命值，不播放玩家命令确认音；已有移动、冻结、敌对免碾压占用、无出口和跨层控制保持。该批只承担全友军步兵物理阻挡，未校准混合占用、其他机车的强制散开或完整原版重试/帧调度。Scene50旧档保持没有该强制反应的结果。

同批自然对局暴露了本项目交通控制的另一处死锁：车辆已在等待格，另一辆仍向该格退让。Scene51在既有退路出口重选时查询阻挡者等待前缀之后的实际离位步，继续使用原目标和合法路径；此交通修正不构成原版AI一致性证明。独立World机制、复制App12与AI的现场续跑、原种子原窗口的自然对局分别验收，不能互相代替。 该检查点的雪谷固定对局未通过；后续局部观察修正的新局已在173872tick内结算，最终完整Release为183/183，相关ASan为8/8，另有一次ASan现场副本诊断通过；本批验收记录见`review_out/ra2-snow-outcome-20261123/acceptance-audit.json`。

相邻窄格内的移动单位互占下一格时，按稳定实体 ID 顺序尝试临时退让；保留正在前往会车点的等待路径，仅重复等待点本身已被占住时允许替换。退让规划把另一单位的最终停车点视为未来障碍，沿普通移动路径完成，保留原终点、攻击移动状态和排队命令；警戒、定身及非盟友不参与。通道调度不得假定未参加穿行准入的本地停车单位会让开，退让规划按其实际硬占用处理。反向退让请求按 tick 和实体 ID 每八 tick 错峰重试，避免原地失败双搜索持续抢占共享预算；无需额外随机数或存档计时字段。普通空地停车也使用保留路线和其他单位目标的连续让路，移除旧的邻格瞬移推让。AI 仅在匹配设施有已完成订单时，以实际占用寻找清口路线；密集队列先挪队尾，受保护或非己方单位不会被强制挪走。单位实际插值被阻挡时释放未能使用的本 tick 下一格预约，避免先占预约却无法前进的单位反过来困住能够驶离的同伴。通道准入本身造成的入口互锁也可触发相邻互占下一格的让行，按 tick/实体 ID 每八 tick 错峰请求；通道内已开始的等待点退让路线保留到完成，暂缓新进入者，避免门控在每个 tick 把部分位移改回原方向。该调度属于本项目交通模型，不宣称与原版引擎的局部避让算法一致。

紧凑路口（最多 64 个相连开阔格，连接至少三个不同窄道口格）与相连车道共用准入区域，避免四向流各自占满出口。较大的等待场保持独立；物理上的开阔格仍可供让行。路网空闲且当前方向无人等待时可提前交接，不空耗整段时间片。分类不会因为先查询开阔格而漏合并路口。以上为本项目的确定性交通协调实现，不是原版寻路规则或全路网无死锁的声明。

集结点是当前融合生产交互：兵营、重工、船厂、空指与复制中心支持设置/清除，新单位按自身通行域选择落点。精炼厂保持自动采矿，不显示无效的集结能力；新空指默认停机，有集结点时新机起飞。旧存档的非负空指集结坐标会按保存值生效（旧默认与手设位置无法区分），清除后可恢复停机。采矿仍采用现有 DockUnload=(3,1) 与卸矿范围近似，返厂会选择可达卸矿位置或备用己方设施；不把这些工程边界修复宣称为官方停靠公式已校准。

## 基准、口径与状态

尤里新兵 `PsychicJab` 已与心控弹头分开：使用新增 `SAFlame`，保留心控单位的 `Psychic`。本轮可核对的本地证据为 `tools/ra2pack/game/ra2md.mix` 内 `localmd.mix/rulesmd.ini`（SHA256 `06761dd7f714e7d9400216ec3c06109ec5c1461f6a0727be7401eb9d8b0f6d05`），其中 `PsychicJab.Warhead=SAFlame`，11 装甲倍率为 `1,0.8,0.8,0.5,0.25,0.25,0.75,0.5,0.25,1,1`。这是本机 YR 基础包规则证据；未找到本机 `expandmd01.mix` 的对应最终补丁规则，不将本项表述为完整 YR 1.001 校准。其他弹头矩阵未作本轮调整。

AI 的地面部队跨海投送为自制策略：有独立陆块时配置运输船，现有步兵与可装载战车通过真实登船、移动、卸载指令执行运输；登陆队按可见敌人与所在陆块的迷雾继续侦察/作战，运输船返航。通用两栖运输船按本地 `rulesmd.ini` 的 LCRF/SAPC/YHVR 校准为尺寸总量 12、乘员尺寸上限 6；普通步兵尺寸 1，普通战车 3，MCV/天启/磁电/主脑 6，狂兽/恐怖机器人 2；IFV 尺寸上限为 1。载矿量、生命、军衔、冷却、箱子增益和 IFV 等载具内乘员随货舱保存，货舱内计时效果继续衰减。World 当前格式为 v25（RA2WRLDP），嵌套载员入校验。仍与活动心控/寄生实体相连的单位暂拒登船，避免装载清除关系造成状态丢失；这是当前工程限制，不作为原版兼容规则声明。融合静态表的高射炮车仍为`Cargo=0`；当前RA2来源包早已覆盖为HTK容量5、单体尺寸上限2，此前的差异文字未区分这两层。Scene55修正来源准入仍额外限制步兵的缺口，恐怖机器人尺寸2可进入履带车与夜鹰；IFV仍按尺寸上限1拒绝。两机器人与一名普通步兵共占5格，载满后按实际尺寸拒绝新乘员。旧Scene54及更早、YR和融合保持原准入。它复用既有载员身份/属性转换、卸载和持久化，没有新增载员字段；同盟装载、容器易主归属、原版装载距离/动画/完整帧时序仍待校准。原始20组查询与依赖见`tests/fixtures/ra2-sized-transport-reference.json`。 本批Release186/186、ASan15/15通过；六组真实装卸及600tick续档、422份跨构建文件和122次历史续跑检查通过。原种子原窗口自然对局通过，记录为`review_out/ra2-flak-transport-20261123/acceptance-audit.json`。

船厂的当前出厂模型为脚印共边的水面出口：优先南侧中央，再按固定顺序尝试其他紧邻边缘，不跨越阻挡到远处生成。生产与 AI 清口共享这组位置；全部边缘封锁时保留已付款完成项，开放任一出口后只释放一次。陆上工厂保留固定门口。四岸方向与保护/封锁有固定回归，此工程模型不等于原版全部出厂偏移和动画的逐项校准。

资源外观按剩余比例选择八档晶簇显示，并使用与采空后相同的 Rough 底材。当前实现从已有 TIB/GEM PNG 中保留完整可见晶簇及其边缘像素，属于表现近似；尚未逐矿量等级校准原版 SHP 帧。此调整不改储量、产值、再生规则或采矿速度。

基准优先级：

1. RA2 与 YR 英文手册描述玩家可观察到的行为。
2. 最终官方补丁：RA2 1.006、YR 1.001；补丁行为覆盖首发版手册。
3. 对数值、前置、装甲/弹头和引擎标志，以最终版 `rules.ini` / `rulesmd.ini` 为准。YR 1.001 的规则应从 `expandmd01.mix` 提取，不能误用 `localmd.mix` 中的 1.000 版本。
4. 本仓库的 `assets/rules/rules.ini` 是 OpenRA2 的扁平化自定义格式，不是原版规则文件；只能代表当前实现目标，不能作为官方证据。

状态标记：

- **一致**：核心玩家可观察行为已接通；数值仍须用自动化断言锁定。
- **融合**：有意偏离官方，必须保留本节说明或由显式选项启用。
- **部分**：存在可用主路径，但缺少关键边界、数值或专属能力。
- **缺失**：只有名称/数据，或没有可玩的逻辑。
- **待证**：仅从代码静态审计无法证明，须加确定性测试或实玩场景。

## “可玩遭遇战”验收门槛

首轮交付只要求标准 Battle 闭环，但以下各项必须可失败地自动验证：

1. **四阵营开局**：盟军、苏军、尤里、中国各从一辆 MCV 在远离其他建筑的合法地形展开。
2. **经济闭环**：电厂 → 精炼厂和赠送矿车 → 持续采矿卸载；资金不为负，宝石高于金矿，阵营矿车行为正确。
3. **生产闭环**：兵营、重工、雷达/空指、高科、海军和超武前置合法；扣款、暂停、取消、出口堵塞均不丢钱或吞单位。
4. **战斗闭环**：地面、空中、海军可获取合法目标；目标死亡后清理引用；拥堵可重寻；运输可装卸。
5. **电力与超武**：低电状态一致；每阵营至少一项超武能充能、选点、生效、重置；Chronosphere 使用双阶段目标流程。
6. **胜负闭环**：仅当对应规则的失败条件满足时判负；最后存活阵营获胜且对局停止。MCV、采矿车、受控单位和联盟均有边界用例。
7. **长局稳定性**：固定 RNG 的至少 20,000 tick 对局无卡死、负资金、永久无效队列、悬空目标或无法结算。
8. **证据要求**：smoke 的每个 `expect` 必须影响退出码；跳过场景不是通过；关键矩阵项必须有直接驱动 `World` 的确定性测试。
