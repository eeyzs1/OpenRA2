# RA2 / Yuri's Revenge 融合复刻规则基准

本文是 OpenRA2 的玩法契约与差异清单，不是“已经实现”列表。目标是先让遭遇战闭环可验证，再逐项逼近 **Red Alert 2 1.006** 与 **Yuri's Revenge 1.001**；共和国之辉、中国阵营及自制战役作为明确的融合扩展保留，不反向定义官方规则。

## 基准、口径与状态

基准优先级：

1. RA2 与 YR 英文手册描述玩家可观察到的行为。
2. 最终官方补丁：RA2 1.006、YR 1.001；补丁行为覆盖首发版手册。
3. 对数值、前置、装甲/弹头和引擎标志，以最终版 `rules.ini` / `rulesmd.ini` 为准。YR 1.001 的规则应从 `expandmd01.mix` 提取，不能误用 `localmd.mix` 中的 1.000 版本。
4. 本仓库的 `assets/rules/rules.ini` 是 OpenRA2 的扁平化自定义格式，不是原版规则文件；只能代表当前实现目标，不能作为官方证据。

状态标记：

- **一致**：核心玩家可观察行为已接通；数值仍须用自动化断言锁定。
- **融合**：有意偏离官方，必须保留本节说明或由显式选项启用。
- **部分**：存在可用主路径，但缺少关键边界、数值或专属能力。
- **缺失**：只有名称/数据，或没有可玩的逻辑。
- **待证**：仅从代码静态审计无法证明，须加确定性测试或实玩场景。

## 当前规则文件的已知偏差

以下差异可直接由 `assets/rules/rules.ini` 与代码确认，不能标成“官方数值复刻”：

- 核子反应堆 `Power=2000` 已对齐参考表；熔毁有瞬时 AoE + 残留波（非官方辐射场瓦片）。
- MCV 成本已对齐官方常规值 3000；建造厂仍为项目表值，需与最终 rules 核对。
- 已提供 11 类装甲/弹头矩阵，主要单位/防御主武器在 `rules.ini` 已标注 `Weapon.Warhead`（与代码 `withWH` 对齐）；未标者仍走 Legacy `VsInf/VsVeh/VsBld`。
- 官方战役原型轨：盟军 oa01–03 + 苏军 os01–03（`Track=1`）；完整 12+12 地图/FMV 仍缺。
- 当前 `BuildTime`、`Speed`、`ChargeTime` 使用项目自定义逻辑帧语义，不能直接与 rules/rulesmd 的分钟、帧或引擎倍率字段逐字比较。
- 尤里奴隶经济采用可部署 `SlaveMiner` + 自动产奴近似，不是完整官方奴隶矿场建筑语义。
- 当前中国共享幻影坦克、V3、天启、基洛夫、铁幕和核弹等项目是融合配置。
- `GameRules` 的低电、军衔、箱子间隔、矿再生等字段已有主路径接通；仍需逐项核对全部调用点。

## “可玩遭遇战”验收门槛

首轮交付只要求标准 Battle 闭环，但以下各项必须可失败地自动验证：

1. **四阵营开局**：盟军、苏军、尤里、中国各从一辆 MCV 在远离其他建筑的合法地形展开。
2. **经济闭环**：电厂 → 精炼厂和赠送矿车 → 持续采矿卸载；资金不为负，宝石高于金矿，阵营矿车行为正确。
3. **生产闭环**：兵营、重工、雷达/空指、高科、海军和超武前置合法；扣款、暂停、取消、出口堵塞均不丢钱或吞单位。
4. **战斗闭环**：地面、空中、海军可获取合法目标；目标死亡后清理引用；拥堵可重寻；运输可装卸。
5. **电力与超武**：低电状态一致；每阵营至少一项超武能充能、选点、生效、重置；Chronosphere 使用双阶段目标流程。
6. **胜负闭环**：仅当对应规则的失败条件满足时判负；最后存活阵营获胜且对局停止。MCV、采矿车、受控单位和联盟均有边界用例。
7. **长局稳定性**：固定 RNG 的至少 20,000 tick 对局无卡死、负资金、永久无效队列、悬空目标或无法结算。
8. **证据要求**：smoke 的每个 `expect` 必须影响退出码；跳过场景不是通过；关键矩阵项必须有直接驱动 `World` 的确定性测试。

1. 先锁定 MCV 独立展开、生产扣款/退款、采矿、低电、工厂出口、目标失效和标准胜负。
