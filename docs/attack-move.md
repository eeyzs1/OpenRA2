# 攻击移动的目的地与队列

2026-11-18后续LAN54修复同格但未到中心的最终物理路段，World60/App11布局保持；修改前14项失败到专项72项通过。全量155/156的原型窗口失败与其余限制见[同格到达与建造顺序](ai-arrival-and-build-order.md)。下文保留最初批次。

本批为 **World47 / App10 / SourceScene15 / LAN26**，NativeEvents4、NativeProduction1、NativeAI1、NativeCrates1 不变。修复的是一条攻击移动指令被途中战斗覆盖后无法继续的问题，不代表全部单位行为已经达到原版精度。

## 行为

修复前，谭雅杀死途中征召兵后停在 `(6.5,15.5)`，飞行兵停在 `(7.667,15.5)`，原定终点均为 `(35.5,15.5)`；灰熊坦克边走边打可以到达，是正对照。修复后，单位分别保存移动目的地和当前交战目标。战斗结束、目标失效或追击失败后，继续前往已接受的目的地，包括原先指定的桥面层。

追加的移动点各自保存普通移动或攻击移动模式。途中追加不会覆盖当前战斗，也不会把后续普通移动误变成攻击移动。飞行单位同样处理后续移动点。成功执行替代命令会取消旧路线；非法坐标、无效攻击、无法执行的散布等拒绝结果保留原有任务。冻结、寄生、休眠和战机返航补弹是暂停；登载、部署、死亡和归属变化清除任务，防止单位在卸载或解除心控后执行前一任所有者的路线。

已接受目的地随后被阻断时，任务保留原坐标、桥面层和队列。共用每 tick 八次的重寻预算，失败后等待 30 tick 再试；重试扫描起点随已保存的 tick 轮换，避免大量低编号断路任务占满预算。飞行恢复不消耗地面 A* 预算。不能把阻断处当作到达，也不能在恢复时改走 `orderMove` 的近处替代落点。最初下令时的编队分散和落点调整仍按现有规则执行，保留的是实际接受的落点。

自动索敌使用单位攻击状态已经采用的攻击有效性判断。原始 `Immune` 建筑不能通过普通伤害或 C4 摧毁，单位不再反复追击它们；心控、超时空抹除和磁力举升继续使用各自的效果判断。建筑自动开火仍走其独立规则。

## 存档与模块

`world_attack_move.cpp` 负责记录、完成和恢复任务；`world_attack_move_save.cpp` 保存有任务或新队列模式的稀疏实体记录，并参与确定性校验。记录包含所有者、目的地、表面层、重试时间以及队列模式，尾部保存扩展长度。加载校验实体顺序、所有权、坐标、模式、队列长度和重试上界，应用存档损坏时保持当前游戏不变。

World46 和更早的存档按历史状态加载，不推测已经丢失的目的地；旧队列保留历史模式继承方式。验收读取修改前实际生成的两个 World46 应用存档，而不是通过改写新档魔数伪造旧档。应用封装仍为 App10，联机模拟协议提高到 26，避免旧程序参与新语义的锁步模拟。

## 验证范围

入口：`--attack-move-regression <输出目录>`，CTest：`ra2.attack_move`。专项覆盖三类单位交战后到达、混合模式队列、拒绝与替代命令、动态断路及恢复、冻结续档、战机返航补弹、尤里/主脑控制和释放、登载/卸载、部署，以及当前扩展损坏拒绝。

两个原图机制夹具保留 ALL01T 桥梁地形和来源规则，清除其他初始对象、另放置交战对象：一个检查桥下交战后到达同一格的桥面；另一个检查原始谭雅自动 C4 炸毁 DRED 后到达水面终点。这是隔离机制检查。原图正常可见目标指令通关仍由独立的 `ra2.native_playthrough` 检查；这两种证据应分开解释。

独立无窗口探针发现，固定从低编号开始扫描会让 270 个断路任务中只有前 240 个得到重试，后面的谭雅在杀敌后等待到 tick900 仍无法继续。轮换起点后，270 个任务都得到重试，谭雅在 tick214 到达。正式专项加入 0/239/270 个断路任务的对照、地面预算已满时飞行兵立即恢复，以及该调度的存档续跑。夹具明确丢弃已接受路线的缓存并切断实际地形，后来的谭雅仍通过正常交战触发恢复。

公平性修正前，完整 Release 121 项为 120 通过、空战役矩阵 1 跳过、0 失败，1104.72 秒。该成绩属于修正前版本。最终代码相关 Release 26/26 通过（189.50 秒），ASan 50/50 通过（1845.95 秒），未报告内存错误。最终 930 项冻结输入及 ASan 程序的哈希均未变化，八份实际应用存档在两种构建间逐字节相同。完整检查后的变化限于恢复调度实现、专项测试与 Release 程序；各阶段日志、差异和哈希记入本地 `review_out/native-campaign/attack-move-validation.json`。早期失败日志保留在 `build/attack-move-baseline-*`、`build/attack-move-immune-baseline-*` 和 `review_out/attack-move-budget-probe/baseline.log`。
