# 原版高架桥双层通行

盟军第一关的两座高架桥现已接入实际移动、占位、鼠标选层、绘图和续档。桥面上的坦克与符合净空要求的桥下单位可以停在同一 XY 格；步兵和双向战车编队可以过桥。后续已接入 [工程师修桥与净空修正](native-bridge-repair.md) 和 [原始闸门开合](native-gates.md)。部分开局交接已由原始事件执行，完整任务与坍塌尚未实现，不能作为第一关通关证明。

## 原始几何与通行

源地图的九段 `BRIDGE2` 覆盖物形成 27 个桥面格。两条桥轴分别位于 `(82,51..55)`、`(62,57..60)`，各宽三格。原始下层高度为 2，桥面和两端道路高度为 6；原始水面、悬崖、TMP 与覆盖物帧均保留，没有把底层改成单层 `Terrain::Bridge`。

`Map::bridgeCells` 从存活的原始桥体及实际覆盖物重建，是不保存的派生缓存。每个桥面格另有上层节点，A* 在两倍格子空间内查找路径；普通地图继续走原有搜索。只有桥的纵向末端能连接高度相符的岸边，侧面栏杆、四级落差和对角拐角阻挡均不能穿过。海军使用下层，两栖单位可以按指令选择水面或桥面。

物理占位链表仍按 XY 索引，查询、终点分配、每 tick 预约、重寻路及让路按单位所在层过滤。相同格子的另一层不占用步兵容量，也不阻挡车辆。装载、进驻与维修同时核对实际地表高度；卸载洪泛保留来源层并返回实际出口层，不能从桥下直接把乘员放到桥上。传送和磁力落地重新确定目标表面；超时空矿车返厂也会更新所在层。

## 表现、输入与观察

单位绘制在实际表面高度，岸边和桥面之间插值时保留前一层用于连续显示。绘图排序在原有次序上增加桥体遮挡约束：下层单位先于桥体，上层单位后于桥体。当前实际 GPU 截图对照使用处于桥边的海蝎，分别核对桥体覆盖及露出的船体像素。

鼠标通过原生地图的可见或已观察高度选择表面；桥面点击不能选择被桥面遮住的下层单位。桥体高度记忆来源于本地已观察的原始实体，不读取隐藏破坏结果。移动光标按所选单位的通行域检查该表面，右键及排队指令携带表面选择。原图像、调色板与偏移的来源见 [地表对象与覆盖物](native-scenery.md)。

## 状态、兼容与模块

- World 当前写入 v36（`RA2WLD36`），在分层、修桥意图和桥梁破坏开关基础上另存原始闸门阶段与事件实例。前一帧高度与派生桥面缓存不进入模拟校验。
- 应用封套仍为 v10（`RA2GAM10`），继续读取 v9/v8/v7。兼容夹具另覆盖相同 v10 封套中的旧 World v31、v32、v33、v34、v35，不能仅凭封套版本判断内部布局。
- LAN 模拟协议为 v12；命令线格式保持原样。`Move.b=0` 为自动、1 为下层、2 为桥面，越界值在整数运算和修改订单前拒绝。修桥使用 `Repair.b=1`。
- `map_bridges.cpp` 管理表面和分层 A*；`world_bridges.cpp` 管理缓存、层状态和交互高度；`world_release.cpp` 管理连通出口。输入、排序和坐标分别位于 `game_bridge_input.cpp`、`game_bridge_render.cpp`、`game_coords.cpp`。

## 验证

```powershell
cmake --build build --config Release
ctest --test-dir build -C Release -R '^ra2\.native_bridge$' -V
```

`ra2.native_bridge` 使用本机原版第一关的完整 738 对象场景，没有原图资源时明确跳过。场景中的机制夹具临时关闭交战，拥堵夹具另设置受控水道；这些改变不写回导出地图。

检查覆盖真实桥面/水下 A*、坦克和船同格、侧道步兵、双向三车编队、桥下两栖让路、传送、磁力落地、桥上登载卸载及拒绝隔层登船。还覆盖 120 tick 同格续档、移动中离桥与排队返回的 240 tick 校验、应用存读档、无效网络层选择、真实鼠标指令、两种显示尺寸及不透明遮挡像素。

双层通行批（World v32）当时的完整 Release 92 项为 **91 通过、空战役矩阵 1 项按约定跳过、0 失败**，746.27 秒。包含既有自然开局、完整对局、交通、表现、存档与网络检查。这是该批证据；当前修桥批的最终结果另见 [修桥记录](native-bridge-repair.md)。

该批原夹具用台风潜艇得到 491 个遮挡、1510 个露出像素，只证明分层绘图。后续发现漏执行净空标志，已修正台风潜艇通行并将夹具改用原版允许通过的海蝎；新画布核对为 295 个遮挡、1385 个露出像素。物理显示截图仍覆盖 1280×720 与 1920×1080，绘制前后 World checksum 不变。

双层通行批相关 ASan 13 项全部通过，192.99 秒，未报告内存错误。它们属于该批，不能代替后续修桥批的检查，也不是完整 ASan、原版任务通关或人工整局验收。

本机日志和画面位于 `build/native-bridge-*`、`build/native-bridge-audit/`；精简断言在 `build/native-bridge-audit.txt`，完整结果为 `build/native-bridge-full-tests.log`，ASan 结果为 `build-asan/native-bridge-tests.log`。源网格保留在忽略目录 `review_out/native-campaign/bridge-source-grid.json`。

## 仍需实现

桥段被直接移除后会关闭该段桥面，不能继续走过；失去支撑的单位按现有落地/坠落规则处理。水面上不适合停留的战车会被清理，桥下单位保留。后续已接入 [工程师修桥](native-bridge-repair.md) 及 [原图脚本爆破](native-demolition.md)，并执行本关原始禁止普通火力破坏桥梁的开关；原版连续坍塌、残骸帧、溅射、精确伤害与落水表现仍未校准。本文上方版本与测试成绩属于其历史批次，当前格式和验证见断桥记录。

分层通行不等于原引擎全部规则。原版坡型和地表速度、步兵子格、完整视野高度规则、武器射线/抛射物高度、空军净空和桥梁任务事件仍待接入。当前三格高架桥已经有双向与拥堵验收；尚未据此声称任意损坏布局或任意复杂路网均不会拥堵。
