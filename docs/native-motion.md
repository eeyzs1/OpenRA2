# 原始步兵速度、水上动作与正常指令通关

本批保持 World46 / App10，来源场景升级为 SourceScene15，LAN 模拟协议升级为 25。NativeEvents4、NativeProduction1、NativeAI1、NativeCrates1 不变。仍为 109 个定义、74 份军队/建筑资料、738 个原始初始对象。

## 已接入的范围

`world_native_scene.cpp` 为原始步行 Locomotor 读取 `OriginalSpeed`，保存不可变的速度资料。换算为 `min(255, clamp(Speed, 0, 100) * 256 / 100)` leptons / 原始逻辑帧，再按每格 256 leptons、原始 15 Hz、本项目 30 Hz 换算到移动步长。谭雅的 Speed=6 为 15 leptons；GI、动员兵、工程师的 Speed=4 为 10 leptons；狗的 Speed=8 为 20 leptons。显式 Speed=0 不移动，也不增加步行动画时钟。

升星速度同时读取原始 `FASTER` 能力和 `VeteranSpeed` 乘数。本关谭雅没有该能力，工程师也不会因通用升星规则加速；GI 的老兵和精英均使用原始 1.2 倍，不把精英套成通用 1.4 倍。原始规则明确注明这些值是乘数。速度箱继续使用来源奖励箱的永久乘数，原始速度计算保留整数 lepton 截断。

以上换算核对固定版本的 [OpenTS TechnoType 读取](https://github.com/OpenTS-Developers/OpenTS/blob/4e5fd62e930339a03c2c18be53a43a167fcf9a79/code/techtype.cpp)、[步行实现](https://github.com/OpenTS-Developers/OpenTS/blob/4e5fd62e930339a03c2c18be53a43a167fcf9a79/code/walk.cpp) 和本机原始 `rules.ini`。参考资料及获取记录保存在本地 `review_out/native-movement-reference/`。这些资料不能代替 RA2 实机逐帧校准。

谭雅原先已经通过 `canSwim()` / `pathDomain()==2` 走水路；本批没有新增她的两栖通行能力。修复的是此前没有接线的水上画面。导出器使用本机原始 SHP 与 art 序列的 `Swim`、`Tread`、`WetAttack`，各八方向、六相位，两种单位共 288 帧。各姿态共用完整 SHP 坐标与缩放，保留帧偏移，避免逐帧裁剪和放大波纹。运行时按移动、停留、开火选择游泳、踩水、涉水攻击，取消通用陆地投影；桥面或离水后使用陆地姿态。`game_unit_animation.cpp` 提供绘制与点选共用的姿态选择。

水上序列与其他已声明动画一样，在启动时验证全部帧。缺图、越界帧数和非法水上锚点均拒绝加载。播放节奏仍是本项目的表现策略，涉水死亡、特殊待机和原引擎完整时序仍待接入。

## 存档兼容

移动资料由存档内嵌来源场景重建，没有增加逐实体保存字段。Scene14 及更早的来源仍使用历史移动方式，避免旧档读入后速度变化。验收使用实际 World46/Scene14 付费工程师应用存档 `review_out/native-campaign/legacy-native46-movement.sav`，并比较恢复后的逐 tick 校验值。旧档 SHA-256 为 `b40bcab5d311dc34b2d1db2906a68067fb1372788e247f7e468b8636a5485966`。

## 正常指令路线与观察夹具

`native_playthrough` 从原始开局运行，经正常移动、向可见威胁下达攻击、回收基地、付费兵营/工程师、修桥、付费 GI 护送和四个真实奖励箱，再游泳击沉四艘原始 DRED、清除原始苏军基地，等待作者的胜利动作。主流程不增加辅助实体、资金、生命，不传送或直接击杀目标。奖励箱专项中的机制夹具在主流程检查点保存之后运行，通关继续前重新加载该检查点；前置阶段失败立即退出，不读取上一次运行遗留的成功档。

这是一条自动操作路线，包含已知地图目标位置和定期重新下达命令，不代表人工实玩或所有路线已经验收。特别是现有攻击移动在交战后可能丢失原目的地，应另行修复和回归，不能把控制器再次下达移动命令当作该机制已正确。

`native_motion` 另使用明确清空演员的物理/表现夹具，测量三种原始步兵及其三级军衔的实际位移、零速、保存恢复、桥面/离水姿态和点选区域。`water-pose-fixture.png` 仅为这个观察夹具；正常通关的图片和应用存档以 `normal-` 开头，保持正常迷雾和实际位置。

## 验证

实际日志、测试成绩、冻结输入和活动存档摘要以本地 `review_out/native-campaign/native-motion-validation.json` 为准。检查包括原始 288 帧逐像素比对、实际渲染相位、旧档和途中保存恢复、正常指令通关，以及 Release / ASan 回归。

最终 Release 全量 **120 项中 119 通过、空战役矩阵 1 跳过、0 失败**，1008.24 秒；ASan 配置下相关 **42/42 通过**，1409.31 秒，未报告内存错误。首次全量发现的队伍移动时间断言及两处旧场景版本断言已修正后重新跑完整套检查，实际模拟代码没有为这些断言改回旧速度。原始解锁时刻仍为 tick1650，未接管的谭雅到 tick1769 开始原脚本的警戒阶段。

924 项冻结输入与最终 ASan 二进制在验收后保持不变。两种构建均从原始开局经过普通指令，在 tick28692 触发作者胜利，谭雅存活、111 HP，实际走水路 481 tick。付费工程师、四个奖励箱、游泳观察、四舰完成和作者胜利共五份实际应用存档逐字节一致。胜利档为 `build/native-playthrough-audit/normal-authored-victory.sav`，1,206,099 字节，SHA-256 `7827d5dc469bc842e381395648a5b94b3417e96e3d45adb8424257aa23722d67`。

正常视野的 1280×720 / 1920×1080 游泳帧及独立动作夹具均已观察。缺失、超长序列和非法水上锚点还单独检查了 ASan 进程的完整输出：三个包均以预期的素材错误退出，没有把异常退出当作成功拒绝。完整成功断言保存为 `build/native-motion-full-assertions.log` 和 `build-asan/native-motion-final-assertions.log`。
