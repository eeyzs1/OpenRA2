# 来源回收、吸收、克隆与间谍

当前RA2 Scene45/Production8保留原始9阶段、缺省36项目tick的采集核心，并加入单泊位停靠与按资源种类整批卸载，默认每30 tick处理一种资源。转向读取原始ROT，车体、炮塔各有独立计时；原始Drive弯道、完整任务调度与Chrono回厂时序仍有近似。原程序隔离调用答案见`tests/fixtures/ra2-harvest-reference.json`和`tests/fixtures/ra2-ground-reference.json`。旧Scene37/43与缺省历史地图快照、当前YR保留20 tick采集；旧Scene44保留36 tick采集及旧卸矿/转向。新旧关系以[架构](architecture.md)为准。下文为历史经济与间谍批记录。

2026-11-17 批次使用 Scene29 / NativeProduction3 / LAN45，保持 World55 / App11 的状态布局。新增字段保存在嵌入规则文本中；Scene28 / NativeProduction2 及更旧快照继续使用各自历史行为。本批属于审查方案的第二阶段，独立支援冷却、多人矩阵、人工实玩、动态整局性能及后续原版任务仍未完成。

后续 Scene30 / World56 批已实现出生老兵经验与四种独立支援，正在扩大验收，见 [独立支援与经验](source-support-and-veterancy.md)。下文的 44 条断言和一项未修经验失败保留本批历史成绩，不作为后续版本的当前状态。

## 实际问题和修复

修改前的真实命令探针报告 18 项失败，保存在 `review_out/economy-20261116/red.log`。来源 YAGRND 没有 `Passengers`，旧代码却要求驻军容量大于零，导致回收入口不可用；YAPOWR 的 `Passengers=5` 也没有接入。间谍可以进入未标记 `Spyable` 的建造厂，矿厂偷钱使用 40%，停电使用 900 tick，高科额外转走 1500，雷达授予全图视野，空指部授予飞机老兵。

单位准入、实际右键、鼠标光标与 AI 现在使用共同的 World 查询。回收入口不占驻军槽；吸收建筑读取 `Passengers`、`SizeLimit`、`InfantryAbsorb` 和 `UnitAbsorb`。坦克碉堡的 `Bunker=yes` 使用专用的一车槽，不能把未设置的 `Passengers=0` 当作关闭入口。反应炉读取每名乘员的 `ExtraPower=100`，五人增加 500 电力，吸收的步兵不从炉内开火；释放后恢复单位资料并重算电力。

回收使用单位显式 `Soylent`，包括合法零值；未声明时使用该单位当前共同报价。已支付的生产订单仍使用开工报价，取消只退已付款。不会以“限制退款不得超过原支付价”的方式破坏缴获单位回收。

| YR 原始单位 | Cost | Soylent |
| --- | ---: | ---: |
| GI | 200 | 100 |
| 狂兽人 | 500 | 250 |
| 奴隶 | 10 | 0 |
| 谭雅 | 1500 | 750 |

克隆仍付费生产一次，再生成免费副本；新规则使用 `Cloning` / `Cloneable`，保留克隆缸自己的集结点。实际购买一名 GI 后得到两名步兵、余额 9800，把两者送入回收厂后恢复为 10000。该例只证明这条 GI 链路，不能作为所有原版单位回收平衡的结论。

## 间谍规则与原版依据

`Spyable` 缺省为否。两套本地原始包均有 `SpyMoneyStealPercent=.5`、`SpyPowerBlackout=1000`；来源帧转换为运行时的 2000 tick。实际奇数余额 10001 转走 5000，保留 5001；转账同时受双方资金边界限制。分数计算覆盖 64 位账本上限，避免浮点舍入把奇数余额多转走一元。

雷达渗透只把受害方的已探索区域重新遮蔽，保留当前可见区域，不向渗透方授予全图视野。兵营与车辆工厂分别授予原始 InfantryType / VehicleType 老兵生产；`Trainable=no` 工程师不晋级，车辆效果也覆盖船厂实际生产的可晋级舰船。原始船厂未设置 `Spyable`，不能从这个生产加成反推出船厂允许间谍进入。

本地 `GAME.EXE` 进行了只读静态核对，未运行其游戏入口、未修改程序：

| 原版地址或字段 | 观察结果 |
| --- | --- |
| 构造器 `0x457D46`，读取器 `0x459B6E` | `Spyable` 缺省 false，缺失字段继承当前值 |
| `0x452390` 起的渗透函数 | RA2 按雷达、正电力、主超武、BuildTech 成员、Storage、工厂选择单个效果 |
| Rules `+0xB74` / `+0xB78` | 停电时长和偷钱浮点比例 |
| `0x4525E8` | 实验室科技取当前受害 House `+0x130` 的侧别，不使用 BuildTech 匹配序号 |
| `0x4E3722` / `0x4E3768` | Allied / Soviet 偷科技需求分别检查 House `+0x205` / `+0x204` |

两套本地 `BuildTech` 都以 `NATECH,GATECH` 开头，不能直接把列表位置映射为 Allied=1、Soviet=2。RA2 现在依据原函数读取当前受害方阵营；YR 的 GATECH / NATECH / YATECH 保留各自科技身份，即使同时提供 Force Shield。上一批“缴获实验室始终按建筑侧别授予科技”的描述对 RA2 不成立，本批明确修正，新增两种版本、不同所属方的实际渗透用例。

YR 科技与原版单效果的参考为 [Ares 开发者说明](https://ares-developers.github.io/Ares-docs/new/buildings/spyeffects.html)。其中关于 BuildTech 顺序的说明与本地列表存在差异，实现限定于已导入的原始实验室，不宣称支持任意重排的自定义科技列表。尚无独立 YR 二进制校准，不能把 RA2 反汇编称为两个版本均已实机对照。

## 验证与边界

永久专项为 `ra2.source_economy` / `--source-economy-regression`，包含 44 条断言：实际回收、克隆、吸收、释放、供电、坦克碉堡、右键与光标、间谍准入及效果、缴获实验室、实际生产、严格规则拒绝、World55 复演和真实 App11 存读档。已有 `ra2.rules_consistency` 继续执行 77 条断言。

导出器已从原始 MIX 重新生成规则并通过对照检查。扩大选择集和 ASan 的最终结果、冻结输入及跨构建存档对照记录于本地 `review_out/economy-20261116/validation.json`；验证进行时不把之前的 Scene28 全量成绩计入本批。

后续仍需校准国家及难度经济倍率、全部退款与受损比例边界、原版回收演出、克隆阻挡与多设施例外、战斗碉堡精确武器倍率、全部复合建筑效果优先级。支援仍共享充能槽；伞兵瞬时落地和侦察机瞬时揭雾尚未改为完整任务流程。融合与旧快照继续保留历史通用行为，本批不代表完整复刻完成。

首轮扩大选择集为 27/28（343.28 秒），唯一失败为 YR 陆地图在 240000 tick 尚未结算；10730 项输入未变化。真实第 234000 tick App11 不改世界状态继续运行，在第 315623 tick 自然结束，尤里获胜。观察窗口调整到 360000 后重新从开局验证，仍要求实际引擎胜负及每个应用检查点复演一致。这一较长对局也说明 AI 进攻效率和整局时长仍是第三阶段的体验优化项。

最终相关 Release 28/28（363.30 秒）、相关 ASan 24/24（623.96 秒）通过，均无失败或跳过，未报告 ASan 内存错误；每种构建均执行新增 44 条及既有 77 条专项断言。另行执行的 Release 原版首关正常指令通关 1/1（41.92 秒）通过。10730 项冻结输入未变化，五组经济/间谍 World55/App11 存档跨构建逐字节相同；本批没有重跑完整全量，也没有重跑四局自然对局的 ASan。

最终额外探针又复现一项尚未修正的经验边界：经过真实兵营渗透后，付费 GI 以老兵军衔、零经验出厂，再实际击杀价值 1000 的间谍仍停在老兵；正确起点应为 600 经验，随后达到精英边界。证据为本批 `veteran-audit-red.log`，一项失败，不计入上述通过的选择集。下一步优先把出生军衔与经验统一，再推进四种独立支援能力。整体四阶段目标保持进行中。
