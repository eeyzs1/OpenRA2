# 来源棱镜的格子扫描与入格顺序

SourceScene33 / NativeWeapons2 改用原始格子顺序选择棱镜分裂目标，并保存可移动对象进入格子的先后顺序。World58 新增有界状态块；App11 不变，LAN50 隔离模拟变化。Scene32 / NativeWeapons1 继续执行此前的距离排序，旧存档不会被磁盘上的新规则替换。**分裂结算时序仍未完成原版校准。**

## 原程序依据与边界

依据是本地 RA2 `GAME.EXE`，SHA256 为 `fe67fdac5073530a79baec14c4e072b5e7e4c0c462cee9659870c5330e9e6e3e`。只读解析 PE、反汇编与常量传播，没有运行原版入口。证据位于 `review_out/shrapnel-20261117/reference/`。

- `0x462c50` 的分裂函数从命中格的 `FirstObject` 判断是否允许分裂；空格和建筑首对象阻止分裂。它不是仅检查弹丸所指向的实体。
- 范围是子武器 Range 的整数格数。从第一环开始扫描，不重新选择中心格。第一环为 NE、N、NW、W、E、SW、S、SE；后续环按 Y 再 X 排序，距离指标为 `max(abs(x),abs(y)) + min(abs(x),abs(y))/2` 的整数部分。
- 独立提取的半径 0..5 共 89 项与该枚举相符，各半径累计为 1/9/21/37/61/89；覆盖原始两级棱镜分裂所用的范围 3 和 5。更大范围使用同一指标，尚无独立二进制逐项校准。
- 每格只检查对象链首项，跳过原发射者和盟友；没有按护甲倍率或 AA/AG 再过滤。多个建筑地基格可以反复选择同一建筑。剩余数量各消耗两次 `[-2,2]` 随机偏移，产生地面射线。
- `0x473b30` 的入格函数将可移动对象插在链头，将建筑放在链尾；因此实体编号排序不能代表原始对象顺序。桥上的 AltObject 与地面的 FirstObject 分开。

[YRpp CellClass](https://github.com/Phobos-developers/YRpp/blob/master/CellClass.h)、[CellSpread](https://github.com/Phobos-developers/YRpp/blob/master/CellSpread.h) 及 [BulletClass](https://github.com/Phobos-developers/YRpp/blob/master/BulletClass.h) 用于核对类型、结构和方法含义。本批没有独立 YR 二进制校准；在两个本地规则包上通过机制测试，不等于已独立证明 YR 原程序的全部行为。

## 模块与状态

`world_native_shrapnel.cpp` 负责 Scene33 的格环、首对象选择、重复建筑接收和空缺射线。`world_native_lasers.cpp` 保留 Scene32 路径。扫描不去重建筑，也不会越过本格首项去寻找一个更适合的敌人。地面射线进入现有弹头结算，不能把“没有选择盟友”解释成所有射线都不会伤害盟友。

`world_native_cell_order.cpp` 管理单调入格序号、首对象查询及 World58 块。只有实际换格、换层或离开/重新进入地面占位时才更新序号。现有用于寻路的占位链继续按实体编号重建，查询来源首对象时另比较保存的入格序号。重复重建缓存不改变模拟状态；退场清除该实体的序号。计数耗尽时按原相对顺序重新编号。

World58 的追加块含版本、启用标志、全局序号及逐实体序号，检查数量、唯一性、范围、占位状态和尾部长度。旧规则保存一个禁用块；Scene33 缺少该块会拒绝载入。序号和全局计数进入校验和；派生的当前格/层追踪不重复保存。App 载入先验证暂存世界，损坏输入不会替换当前对局。

## 验证与当前限制

修改前同一复现程序为六个控制通过、十个机制失败；当前对象构建后十六项全部通过。新增永久专项在最终 Release 和 ASan 各通过 51 条断言，包括公共攻击、格序、范围边缘、五次建筑接收、五条空缺射线、同格盟友遮挡、入格历史、重建、桥层、退场、World/App 逐帧复演、七种损坏输入、停机战机接攻击命令、乌贼 Stop 脱离，以及测试隐藏窗口。另有 42 条 Scene32 武器断言继续通过。防守者相位冻结用于隔离机制，不作为自然对局证据。

首次 Release 的 151 项非性能检查全部通过。随后修复无发射者的负分裂数递归预算：两版本共四个控制通过、两个超预算漏拒绝，修复后六项全过。该修复后的相关 Release10/10、ASan40/40 通过。

真实对局又暴露命令提交与缓存不同步：尤里八人局 216000 tick、RA2 八人局 144000 tick 的 App 保存失败。旧成功 App 逐帧重放首先在 199395 tick、AI0 发出 ORCA 攻击命令后发现地面入格序号仍未清除。`world_orders.cpp` 现在在 Scene33 攻击命令提交时同步占位；乌贼 Stop 脱离同样同步，新夹具在修正前另有四条失败。两份真实 App 均可重放至原失败点并成功保存。旧 Scene32 路径保持不变。

命令修正后的最终 Release18/18、ASan8/8 通过。最后补上新专项遗漏的隐藏窗口入口，只有 main 和专项测试对象发生变化，模拟对象不变；隐藏窗口专项再各 1/1 通过。没有第二次完整 151 项/40 项最终全绿运行。每轮两构建 560 个对象的哈希记录保留，预算、命令和隐藏入口分别只改变对应源文件及测试对象。

本批不是完整复刻完成声明。

当前仍冻结完整子目标图并同步按子弹先于父弹结算，与此前实现相同。原程序的子弹 MoveTo 没有直接 Detonate，仅凭 Shrapnel 在父弹伤害之前被调用，无法推断原始 Logic 更新时机。本批因此没有声称解决互射、死亡回调、新生对象和逐帧入队顺序。

随机偏移使用项目现有 RNG，不是原版 RNG 的逐值复现。地面射线使用当前伤害和弹道积分；球形高度、原始零扩散落点、地形/叠加对象链、非激光递归弹丸及完整碰撞标志仍需校准。普通地图的部分装饰没有原始对象实体，不能据此声称完整还原 FirstObject。
