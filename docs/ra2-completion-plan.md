## 交付顺序

| 里程碑 | 交付物 | 退出条件 |
|---|---|---|
| M1 RA2遭遇战交付版 | 可作为主要试玩版本的盟苏对战 | BASE/MOVE/RULES/WORLD/PRESENT中对局必需项形成明确矩阵；已知阻塞、坏档、失步与严重手感差异关闭；固定回归与集中试玩通过 |
| M2 原版AI覆盖 | 从原版依据建立的完整普通对手策略 | 经济、建造、生产、队伍与战斗行为均有对照，代表性对局能自然结束；工程策略与原版策略的残余差异明确 |
| M3 完整RA2战役 | 24关原版地图、事件和任务入口 | 每关覆盖开局、关键阶段、胜负、重开、续档与人工通关；共用机制的缺口以实际关卡需求排序 |
| M4 完整复刻验收 | 规则/内容/行为总表关闭的发布候选 | 固定目标补丁基线，所有范围的必需项均有匹配证据，完成系统实玩、稳定性和交付检查 |

M1先形成明确可交付版本。M3在所需共用机制就绪后逐关推进，可与M2按依赖交替，不因无关的AI内部考据长期阻塞战役接入。未来发现的独立问题进入总表，先按交付影响排序，再选择下一个批次。

战役进度单独记录：A01（all01t）为已接入、人工整关验收待完成；A02–A12及S01–S12为待接入/验收。不得把已撤下的原型关卡算入24关进度。

## 已验收批次：MOVE-WALK 步兵移动流程

本批关闭的问题：此前普通RA2步兵把来源速度均摊为浮点位移，已复现的整数位置差异及对应命令/保存/装载衔接现已收敛。验收覆盖以下退出条件；完整原版UI/任务时序与M1其余项目仍开放。

相关模块：`world_pathing.cpp`、`world_native_walk.cpp`、必要的World声明与规则版本，以及`game_infantry_travel_tests.cpp`。只有确需展示插值或持久化时才扩展相应模块；扩展前说明依赖。已有纯机械提取与58份等字节证据保留，不给它添加兼容开关。

这一批的退出条件：

1. 普通速度与八方向的真实Move在原版帧边界匹配捕获数据；覆盖连续跨格和到达，明确原版速度计算的供应边界。
2. 把下令、移动、停步、改令、定身、阻挡和恢复组成可重复的完整操作流程；原版裸机车Stop/MoveTo观测不直接冒充完整UI命令时序。
3. 动画与插值不驱动模拟；展示变化有独立检查，不能用表现字段补齐未保存的模拟状态。
4. 当前命令后、格内、奇偶tick及必要的中断现场能精确续档；实际Scene68行走现场保留其完整结果。新增保存字段须有已证实的状态需求和原子拒绝检查。
5. 保留原有占位、共享原格、阻挡与移动层边界，不以无条件穿过单位或跳过准入消除红测。
6. 在同一稳定输入上完成相关Release、必要ASan和一次完整Release；新回归入口/运行时源文件的产品ON/OFF检查按开发流程执行。两张固定原图继续使用922/923和180000tick窗口，不调种子、窗口或胜负断言。

该批稳定前不扩展新的散开、雾区或载员研究。发现直接阻塞本批的依赖时记录因果并调整范围，其余问题进入总表等待排序。完成后先回到M1验收矩阵选择缺口，再决定是否进入下一机制。

## 验证与进度汇报

- 每个批次对应本表ID及一个可观察问题。相关的速度/位移/命令/保存联动作为同一流程收敛，稳定后再执行一次全量；保持机械提取与行为修改的证据分离。
- 叶子改动先做准确的相关检查；生命期、引用、解析等按风险选择ASan。代码再次改变、失败或存在未解决问题时，才重复相应验证；不得省略批次最终必需检查。
- 原版研究只服务当前已声明的差异，得到足够实现/验收的证据后转入真实流程验证。新增样本数量本身不算交付进展。
- 每批保留一份基线、失败记录、必要的状态输出和最终收据；重用已有未改变的证据，避免为每次小编辑复制整套档案。既有封存记录不删除或改写。
- 汇报固定写明：关闭的ID/玩家能力、实际证据、未关闭的主要缺口和下一优先项。没有完整验收矩阵前不报总完成百分比或承诺完工日期。
